Zoro - Privacy Policy

Last updated: 2 October 2026

What Zoro is

Zoro is a private desktop assistant. I, Dr. Srinivas Patel Punyala (Zoro NutriDiet), am its only user. It runs on my own Windows laptop and helps me make and publish evidence-based nutrition videos on my own YouTube channel. Zoro is not offered to anyone else.

YouTube API Services

Zoro uses YouTube API Services. By using Zoro, you agree to be bound by the YouTube Terms of Service. Information that Zoro gets through YouTube API Services is also subject to the Google Privacy Policy.

Google sign-in and scopes

Zoro signs in to one Google account, my own, through an OAuth 2.0 Desktop client. It asks for these scopes:

  • youtube.upload: to upload my videos and set their thumbnails.
  • youtube.readonly: to read my own channel details and my video statistics.
  • youtube.force-ssl: to upload subtitle and caption tracks to my videos, to check which tracks they already have, and to read comments on my own videos.
  • yt-analytics.readonly: to read analytics for my own channel.
  • calendar.events: to add and read events in my content calendar. This is not YouTube data.

Publishing

Zoro publishes to YouTube only through the official YouTube Data API. It uploads a video when I ask it to, or on a schedule I set up. By default, each upload carries the altered or synthetic content disclosure (containsSyntheticMedia) and is marked as not made for kids.

For a manual upload, Zoro opens youtube.com/upload in my normal web browser and I upload the video by hand. Zoro does not control that page.

Zoro has no YouTube Studio browser mode and does not use any third-party upload service for YouTube.

Comments

Zoro reads comments only on my own videos. Before it reads them, it checks that the video is on my channel. A Groq-hosted AI model groups the viewer questions so I can plan videos that answer them. Zoro never posts, edits or deletes comments. The exceptions listed under AI processing also apply to comment text.

Public research data

Zoro also uses a YouTube Data API key to read public data: public channel details, public video lists and statistics, search results and trending charts. I use this to study what works on health channels. Zoro never takes any action on other channels.

Zoro has no code that scrapes YouTube pages or downloads videos or captions. Its browser agent and its page-reading tools (fetch_url and crawl_docs) are blocked from YouTube pages, including redirects to them. One general tool for calling web APIs (http_request) does not block YouTube addresses yet.

How the data is used

Zoro uses this data only to do what I ask, such as publishing a video, preparing a performance report or planning content. It does not sell data and does not use it for advertising.

AI processing

When a chat, agent task or workflow gets data from one of Zoro's YouTube API tools, Zoro marks that task as private. This covers my own channel analytics, my video statistics, the text of public comments on my own videos, and public channel and video statistics, search results and trending charts. From then on, every AI call in that task uses only open models hosted by Groq. The same applies to any helper task it starts and to the chat it belongs to. A chat stays private after the first answer that used YouTube data.

In a private task, Zoro refuses its Gemini tools: Google search grounding, image and video generation, Gemini text-to-speech, screen and camera vision, video summaries and the browser agent. Web search uses only plain DuckDuckGo or Bing results, and the Groq model writes the answer. Lessons saved in a private task are stored without a Gemini embedding.

Groq is a third-party AI service, so this data is sent to Groq. Groq's own policy says that, by default, it does not keep inference data (see Groq: Your Data). Zoro does not check or change Groq's settings.

Zoro uses Groq's free tier, which has rate limits and daily limits. If no Groq model answers during a private task, Zoro tells me it cannot process the YouTube data right now. It does not pass the data to another AI.

Voice

In a voice conversation, my spoken words go to Google's Gemini Live API. If an answer uses YouTube data, Zoro shows it on my screen only. Gemini Live gets a short fixed notice instead of the answer. Zoro also stops sending my screen to Gemini for the rest of that voice session, even if it reconnects.

Answers that use YouTube data are read aloud only by voices that run on my laptop, or not at all.

Known exceptions

The code does not yet keep YouTube data private in these cases:

  • Self-review. Each night, Zoro sends short excerpts of the past 7 days of its tasks to Gemini to look for gaps in its skills. Each week, it sends short excerpts of the past 30 days of tasks to Gemini to suggest new workflows, and saves those suggestions as files. Neither step leaves out private tasks, so the excerpts can contain answers based on YouTube data and the text of viewer comments.
  • Learning topics. Zoro may turn viewer questions, or a chat about my channel, into short learning-topic names such as "iron in spinach". Topics that Zoro takes straight from my analytics or comments are researched privately and deleted after 30 days. Topics added by the comment FAQ workflow or by the summary of a chat are saved as ordinary topics, and so is a YouTube topic whose name already exists as an ordinary topic. Zoro keeps those topics, may research them at night with Gemini and web search, and may list them in daily and weekly notes that Gemini writes.
  • Nightly video search. Zoro's nightly learning uses YouTube Data API search to find public videos on its topics. It sends the links of those videos to Gemini so that Gemini can summarise them, and it keeps the links in its list of sources. This step does not run as a private task.
  • Saved data opened later. A saved YouTube report or data file is not private on its own. If I ask Zoro in a new task to open one, or I paste YouTube data into a new task or a clipboard hotkey, Zoro may not mark that task as private. The text can then go to Gemini.
  • Screen. If I share my screen with Gemini Live, or use Zoro's screen tools or hotkeys, while YouTube data is on screen, the image goes to Gemini. A new voice session sends my screen until its first answer that uses YouTube data. Zoro's browser agent, which runs on Gemini, is not blocked from Zoro's own local dashboard or from saved report files.
  • Search queries. In a private task, the search queries that the Groq model writes can contain words from YouTube data. They go to DuckDuckGo or Bing. Private research on a learning topic also sends queries to PubMed, arXiv, GitHub, Hugging Face and YouTube search. A private task can also read web pages it chooses.
  • Other services. In a private task, Zoro does not block the tools that send text elsewhere: notifications to ntfy or my Telegram bot, web API requests (http_request), shell commands that a task runs, my local n8n automations, and my local Open Notebook app, which passes text to the embedding service it is set up with. Text sent this way can contain YouTube data.
  • Daily notes. My own typed messages from a chat that used YouTube data can appear in the daily notes that Zoro writes with Gemini.
  • Whiteboard narration. When Zoro draws a whiteboard explanation in a private task, the dashboard may read the steps aloud with any browser voice, including online voices from Google or Microsoft.
  • My own words and errors. My spoken questions always go to Gemini Live, so if I read out YouTube numbers, Gemini hears them. If a private answer fails with an unexpected error, Gemini Live may receive the error message.
  • Other AI apps. Other AI apps on my laptop, such as Claude Code, can connect to Zoro through MCP. They get a short notice instead of any answer built on YouTube data. They can still read the names of Zoro's skills and research topics, and some of these may come from viewer questions.

Other tasks

For tasks that do not use YouTube API data, such as writing scripts or research on other sources, Zoro may use the Google Gemini API. The free tier of the Gemini API may use prompts to improve Google products (see the Gemini API terms).

When I ask, Zoro may send the link of a public YouTube video to the Gemini API so that Gemini can summarise the video. I do this in a separate task, because Zoro refuses Gemini tools in a task that has used YouTube API data. The nightly video search above is the exception. Zoro does not download videos or captions.

Text is sent to an AI model only to carry out my requests and the scheduled jobs I set up. It is not sold and is not used for advertising.

Telegram and notifications

If I chat with Zoro through my own Telegram bot, Zoro's replies pass through Telegram. These replies may include my own channel analytics or summaries of viewer questions. When a workflow waits for my approval, Zoro can send me a preview of up to 600 characters through Telegram or ntfy, and the preview can contain YouTube data. If I turn on ntfy, Zoro sends short notifications to my own ntfy topic. These can contain YouTube data too.

Storage

Zoro keeps its data on my laptop. OAuth tokens are encrypted with Windows DPAPI, so only my Windows account can read them. API keys are kept in Windows Credential Manager. Other data is kept in local files and a local SQLite database. There is no hosted Zoro server. Zoro's only server listens on 127.0.0.1 on my laptop.

Zoro keeps its last 14 daily backups on my laptop. A new backup leaves out the YouTube data that the 30-day job covers. Its copy of the database is redacted the same way, and if that fails, the backup holds no database at all. When the 30-day job, Disconnect or "Delete stored YouTube data" runs, Zoro rebuilds the older backups by the same rules. YouTube data that the job does not yet cover (listed below) can still be in backups.

Zoro also keeps a local git history of its brain folder on my laptop. YouTube reports and comment FAQ notes are kept out of new commits. Other files listed below can enter that history, and older commits are never rewritten.

Sharing

Zoro does not sell Google user data or share it with anyone for their own use. Data leaves my laptop in these cases:

  • Calls to Google's own APIs (YouTube Data API, YouTube Analytics API, Google Calendar API).
  • YouTube data sent to open models hosted by Groq, as described above.
  • Text for other tasks, my voice conversations and links to public YouTube videos, sent to the Gemini API. The cases under Known exceptions also send text to Gemini.
  • Replies, approval previews and notifications sent through my own Telegram bot and my own ntfy topic.
  • Search queries sent to search services, and text that a task sends through web API requests, n8n or Open Notebook, as described above.

How long data is kept

A job deletes or redacts the YouTube data Zoro has stored once it is 30 days old. It runs when Zoro's background service starts and then every 24 hours while the service runs. If the service is not running, for example when I use only the command line or Telegram, the job waits until the service starts again.

It deletes:

  • raw YouTube API files in Zoro's research folder;
  • YouTube reports and comment FAQ notes;
  • lessons saved from YouTube data;
  • learning topics taken straight from my analytics or comments;
  • YouTube experiments.

It redacts:

  • chat replies that used YouTube data, the chat summaries made from them, and the lessons taken from those summaries;
  • Zoro's records of agent tasks that called a YouTube API tool, of the comment FAQ workflow and of the tasks that started it, with their tool log rows and saved workflow checkpoints;
  • YouTube lines in daily notes.

Deleted text is overwritten in Zoro's main database file, and the database is compacted after each pass that changed it.

Records of my own uploads (the video IDs and links of videos I uploaded to my channel) are kept until I press Disconnect or "Delete stored YouTube data". Copies of these links in Zoro's own tool logs and task records can remain after that.

The job does not yet delete:

  • Zoro's records of some private tasks: other workflows that used YouTube tools (for example the daily briefing, which can use YouTube search), tasks that asked an expert agent that used them, and later turns of a private chat or voice session. The chat messages themselves are redacted.
  • Tool log rows of other tools used in a private task, such as charts, whiteboards, notifications and web requests. Each row keeps the tool's input and up to 500 characters of its output.
  • Files that a private task saves outside the reports folder, such as study notes and notes in the notes folder, and data files that cannot carry the YouTube tag. These go into backups and git.
  • Learning topics saved as ordinary topics (see above), skills and expert agents created in a private task, Zoro's source and evidence lists, and its workflow suggestion files.
  • Charts, whiteboard drawings, audio files, slide images, caption files and screen recordings made from YouTube data. Whiteboard drawings go into backups and git.
  • Log files, which can hold short pieces of a private answer or video IDs.
  • Copies already sent to Telegram, ntfy or other services. Zoro cannot delete those.

Zoro is told to write only general lessons into its skills, in rounded words and without exact YouTube statistics. Skills are kept permanently, and the code does not check what an agent writes into them.

Google API Services User Data Policy

Zoro's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Revoking access

The Disconnect button in Zoro first revokes the token at Google. Then it deletes the local token files and all the stored YouTube data that the 30-day job covers, at any age, including the records of my own uploads. It also rebuilds the older backups. If revoking at Google fails, Zoro shows a warning and a link to the Google permissions page, where I can remove access myself.

A separate "Delete stored YouTube data" button deletes the same data even when Zoro is not connected to Google.

Neither button touches a workflow that is still running or waiting for my approval at that moment. Neither removes the items that the 30-day job does not yet delete.

If I remove access on the Google page instead of pressing Disconnect, Zoro does not notice. Its stored YouTube data is then removed only by the 30-day job or the delete button.

Access can also be removed at any time from the Google security settings page at security.google.com/settings/security/permissions (also at myaccount.google.com/permissions).

Cookies

This website sets no cookies and has no tracking. Zoro keeps my Instagram and Facebook sign-ins in a separate local Chrome profile for posting to those sites. YouTube and Google are not used through that profile; Google access uses the encrypted OAuth token. That profile stays on my laptop and is not shared. Zoro does not place cookies on anyone else's device.
